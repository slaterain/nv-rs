# GOG 1.4.0.525(a), offline installer build 55068

This profile identifies the en-US executable with SHA256
`89e7020487e80f20ddc92ea641c4433b2c6839a82f45a076e414d167d11dd0fe`.
It does not identify older GOG builds, Galaxy features, or arbitrary patched
executables. No executable bytes or game assets are included in the repository.

## Evidence

Measured from an owned, unmodified GOG installation on 2026-11-19:

- The four mapped sections have the Steam reference addresses and sizes.
- `.data`, `.tls`, and `CONST` match the existing reference hashes.
- In a private in-memory `.rdata` copy, replacing its single `GalaxyWrp.dll`
  name with `steam_api.dll` restores the existing Steam reference hash exactly.
- The 11 wrapper imports use the same names and IAT slots as the Steam APIs.

The profile verifies the mapped sections and this build's `.text` fingerprint.
The wrapper exports use the existing offline/no-client implementations; nv-rs
does not load GalaxyWrp.dll, add Galaxy achievements or change the installation.
Synthetic tests exercise wrapper resolution without game files. Optional local
integration tests use `NV_GOG_EXE` to check the owned executable and mutations.

## Play validation and limits

An Apple M1 Max native play build passed the executable check, rendered the
main menu, and allowed interactive play inside Doc Mitchell's house and outside
in Goodsprings. That Mac run also needed the separate Unix profile/profiler
variable-collision fix; this change does not contain that launcher fix.

Two real-thread runs stopped: one read address `00000008` in `00a9b570` (alpha
sorting); another read code address `00acbb70` as data in `00b66520` while leaving
the house. Neither cause is established. A stepped-thread comparison has not
repeated a stop so far, which does not establish a concurrency fix. No original
Steam-executable or original-game execution comparison was available.

This is executable recognition and wrapper-import compatibility, not proof of
stable gameplay or campaign completion. Windows/Linux play and save/reload
validation remain outstanding. Next: platform CI and independent review/play
testing, followed by reproducing the rendering faults separately.
